v3.4.5 - the fresh-install default backend list now carries all four internal backends (sap, zabbix, rd, tutorials), matching the supervisor discovery list and the Kerberos installer seed; a brand-new laptop knows about the R&D (Windchill/Polarion/SVN) and tutorials backends out of the box rather than depending on runtime discovery. rd and tutorials stay auth=negotiate even on the legacy key-based seed path (rd is Kerberos-only; tutorials is no-auth). Bundled offline-fallback tool snapshot refreshed to pa_v2 0.1.44 (was 0.1.22). No change to existing laptops' backends.json (user config always wins).

v3.4.4 - one-click install fix for Claude Desktop 1.12603.x. The bundle still declared the legacy DXT manifest key (dxt_version), inherited from the 2.4.1 baseline; the new Desktop build no longer recognises the server block from such a manifest and the packed-.mcpb one-click install stopped completing (a hand-extracted copy still ran). build-mcpb.ps1 now emits the current MCPB key manifest_version "0.3" instead. No shim logic change.

v3.4.2 - refresh the connector-directory metadata (this description and the tool list) to the current pa_v2 catalogue. Earlier 3.x builds carried the v2.4.1 blurb and the old V1 tool names (get_vendor_aging, ...) because the build only bumped the manifest version and never rewrote these fields. build-mcpb.ps1 now syncs the tool list from the bundled catalogue and reads this text from the repo, so it cannot re-freeze.

v3.4.1 - refresh the bundled offline-fallback catalogue (loaded only when the backend is unreachable at first launch) from a stale 104-tool V1 snapshot to the live 175-tool pa_v2 catalogue, including the R5 G/L tools (pa_extract_bsis, pa_extract_bsas, pa_gl_open_items, pa_gl_account_balance). The online path already fetches the live catalogue at first launch.

v3.4.0 - call-time backend attribution: every response is stamped with which federated backend served it, so a multi-backend setup reports its source instead of guessing.

v3.3.0 - auto-refresh: the shim probes each backend's /health and re-fetches /tools when the server version or tool count changes, so a server-side tool addition appears without a manual reload.

Auth: Kerberos/SPNEGO (negotiate) is the default for human users - the shim mints a SPNEGO token from your Windows logon via SSPI, so there is no key on disk. Service identities (headless callers) can still set an X-Punch-Auth key per backend in backends.json.

Requires a domain-joined machine for Kerberos and the punch-analytics server (http://ai.punchpowertrain.com:3000).
